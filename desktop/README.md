# Десктопный прототип для Windows

Tauri открывает React-интерфейс в WebView2 и автоматически запускает упакованный
Python/FastAPI-backend. Пользователю не нужны Docker, Python, Node, Rust или свой
сервер. WebView2 устанавливается установщиком при отсутствии (для этого нужен интернет).
После установки учёт работает локально без интернета.

## Хранение и запуск

- Каталог данных: `%LOCALAPPDATA%\com.filamenttracker.desktop`.
- База: `filament.db`. Она отделена от каталога установки и не перезаписывается обновлением.
- Последние пять резервных копий перед запуском: `backups\filament-*.db`.
- Журнал ошибок запуска: `desktop.log`.
- Одновременно допускается один backend для этой базы; повторный запуск показывает ошибку.
- Backend слушает только `127.0.0.1`, порт выбирается автоматически.
- Оболочка получает одноразовую ссылку по закрытому stdout-каналу. Ссылка создаёт
  случайную httpOnly-сессию. Пароль и экран входа в локальном режиме не требуются.
- При закрытии окна или аварийном завершении оболочки закрывается stdin-канал,
  backend завершает работу. Веб/Docker-режим сохраняет прежнюю JWT-авторизацию.

Существующая серверная база автоматически не переносится. Для пробного переноса
закройте приложение и сервер, сделайте копию исходной SQLite-базы и положите её
как `filament.db` в каталог данных приложения. Не копируйте открытую базу.
Восстановление копии пока ручное: полностью закройте приложение, сохраните текущую
базу отдельно и скопируйте выбранную копию на место `filament.db`.

## Ручная резервная копия файлом

В десктопе откройте «Настройки → Резервная копия → Скачать резервную копию».
Приложение подготовит файл вида `Filament-Tracker-0.3.11-backup-ДАТА-ВРЕМЯ.db`
и передаст его на скачивание. Проверьте папку «Загрузки» или выбранное место
сохранения. Закрывать приложение для создания копии не нужно; интернет не требуется.

Это полный снимок локальной SQLite-базы: катушки, справочники, валюты,
правила дозаказа и версия миграций. Используется SQLite Backup API, а не простое
копирование открытого файла. Снимок содержит сохранённые данные на момент копирования.
Файлы ручных копий не удаляются ротацией пяти автоматических копий. Их можно
перенести на другой диск или в своё облако. Приложение само никуда их не отправляет.

Для восстановления полностью закройте приложение, сохраните текущую базу отдельно
и скопируйте выбранный файл в каталог данных под именем `filament.db`.
Интерфейс восстановления пока не реализован. При восстановлении данные,
добавленные после создания копии, будут заменены содержимым выбранного файла.

## Сборка на компьютере разработчика

Требуются Windows x64, Node 22+, Python 3.13, uv, Rust/Cargo (MSVC toolchain),
Visual Studio Build Tools с компонентами **Desktop development with C++**
(MSVC и Windows SDK). Это зависимости разработчика, не пользователя.

### Установка MSVC Build Tools

1. Скачайте установщик с [официальной страницы Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/).
2. Запустите его и разрешите установку в запросе Windows.
3. На вкладке «Рабочие нагрузки» выберите **«Разработка классических приложений на C++»**
   (**Desktop development with C++**).
4. Справа в составе установки проверьте наличие **MSVC для x64/x86** и
   **Windows 11 SDK** (либо Windows 10 SDK). Оставьте рекомендуемые компоненты этой нагрузки.
5. Нажмите «Установить» и дождитесь завершения. Если установщик попросит перезагрузку,
   выполните её. Затем откройте новый терминал в PyCharm.
6. Из корня проекта запустите `./scripts/build-desktop.ps1`.

Полная Visual Studio IDE не требуется. На этом компьютере WebView2, Rust toolchain,
MSVC Build Tools и Windows SDK найдены; полная сборка установщика прошла успешно.
Источник требований: [документация Tauri](https://tauri.app/start/prerequisites/).

Из корня репозитория:

```powershell
.\scripts\build-desktop.ps1
```

При нестандартном пути Python:

```powershell
.\scripts\build-desktop.ps1 -Python 'C:\path\to\python.exe'
```

Результат: `desktop/src-tauri/target/release/bundle/nsis/*-setup.exe`.
Версия установщика берётся из `backend/pyproject.toml` при упаковке.

Это служебный каталог Tauri: `target` — результаты компиляции Rust,
`release` — оптимизированная сборка, `bundle/nsis` — установщик Windows.
Готовый `setup.exe` можно скопировать в любую удобную папку и передать пользователю.
Путь к установщику не определяет расположение пользовательской базы.

## Главный экран

На странице «Остатки» кольцевая диаграмма показывает оставшийся вес по цветам.
Рядом расположена таблица с весом и долей каждого цвета. Катушки разных материалов
с одинаковым названием цвета суммируются; текущие фильтры применяются к диаграмме.
Используется сохранённый оттенок, затем цвет из палитры, иначе нейтральный серый.
Катушки с нулевым остатком в диаграмму не входят.

## Бренды

В «Настройки → Бренды» добавьте нужные названия один раз. В форме катушки
бренд выбирается из выпадающего списка. Если справочник пуст или бренда нет,
под полем есть ссылка на настройки. Старые записи с брендом, которого ещё нет
в справочнике, сохраняют своё значение при редактировании.

С версии 0.3.8 справочник предзаполнен: Anycubic, Bambu Lab, Bestfilament,
Creality, ELEGOO, eSUN, FDplast, Fiberlogy, Flashforge, Overture, Polymaker,
PrintProduct, Prusament, REC и SUNLU. Дополнительной миграцией добавлены
**DeepLee** и **Star Plast**, а также базовый бренд **Нонейм** — всего 18 брендов. Написание проверено на сайтах
[DeepLee](https://deeplee3d.com/) и [Star Plast](https://star-plast.com/).
Бренды добавляются миграцией при первом запуске
или обновлении существующей базы. Пользовательские записи сохраняются; совпадения
проверяются без учёта регистра и пробелов по краям.

## Быстрое добавление катушки

Обязательны материал, цвет, вес полной катушки и остаток. Бренд можно не выбирать:
в этом случае сохраняется «Нонейм», который добавлен в базовый справочник.
Для новой катушки
по умолчанию указан вес 1000 г; при изменении общего веса остаток меняется вместе
с ним, пока вы не зададите остаток вручную. Цвет выбирается в палитре или задаётся
названием; пустое название не принимается. Старые записи без цвета доступны для
просмотра, но при сохранении через форму нужно указать цвет.

Цена, валюта покупки, рейтинг, магазин, дата и заметки собраны в блок
«Дополнительно: покупка, рейтинг и заметки». При добавлении он свёрнут,
при редактировании раскрыт. Любые подробности можно заполнить позже.

Пустая цена означает «не указана», 0 — получено бесплатно. Для неизвестной цены
в таблице показывается прочерк; цена за килограмм не вычисляется. Статистика
учитывает только известные цены и сообщает число катушек без цены. Остатки
учитываются у всех катушек, средний рейтинг — только у оценённых.
Существующие цены сохраняются миграцией, работающую базу вручную менять не нужно.

## Проверка обновлений

В десктопном приложении откройте «Настройки → Обновления приложения» и нажмите
«Проверить обновления». Отображаются установленная версия и результат сравнения
с последним опубликованным стабильным GitHub Release. При наличии новой версии
кнопка «Открыть страницу релиза» откроет системный браузер для скачивания установщика.
Закройте приложение перед установкой обновления поверх текущей версии.

Проверка выполняется только по нажатию кнопки, требует интернета и не отправляет
содержимое базы на GitHub. Git и GitHub-аккаунт пользователю не нужны. Пока релизы
не опубликованы, приложение сообщает об этом. Без сети учёт продолжает работать.
Загрузка и установка обновлений автоматически не выполняются; в веб-версии этого блока нет.

## Сборка через GitHub Actions

Workflow `Desktop Windows build and release` собирает frontend и backend,
проверяет упакованный backend и создаёт NSIS-установщик.
При ручном запуске из ветки результат доступен как artifact `Filament-Tracker-Windows`.
При отправке тега `vX.Y.Z` дополнительно публикуется GitHub Release с установщиком
и файлом контрольных сумм `SHA256SUMS.txt`. Тег должен совпадать с версиями backend,
frontend и Tauri; при несовпадении сборка останавливается до публикации.

После коммита изменений в `dev` выпуск версии 0.3.11 выполняется так:

```powershell
git push origin dev
git tag -a v0.3.11 -m "Filament Tracker v0.3.11"
git push origin v0.3.11
```

Отправка тега запускает публикацию автоматически. Перед ней локально проверьте
установщик и бренды. Для следующего выпуска используйте новый номер версии и новый
тег; опубликованные теги не передвигайте. Персональный токен не нужен: workflow
использует встроенный `GITHUB_TOKEN`, право `contents: write` выдано только этапу публикации.

Установщики для пользователей появятся в
[GitHub Releases](https://github.com/lastloony/Filament-Tracker/releases).
Workflow начнёт работать после отправки этих изменений в GitHub; локально добавление
конфигурации само по себе ничего не публикует.

## Проверка backend

После упаковки:

```powershell
.\backend\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
```

Проверка запускает настоящий `.exe` с временной базой: миграции, доступ только
с сессией, одноразовый вход, запрет постороннего Origin, CRUD, статистика,
отказ второго экземпляра, остановка по stdin, сохранность после перезапуска
и читаемость резервной копии. Рабочую базу тест не открывает.

## Статус и ограничения

Это прототип, не готовый публичный релиз. Установщик пока без цифровой подписи:
предупреждение SmartScreen принимается как известное ограничение.
Локально успешно собран автономный backend и пройдена интеграционная проверка;
frontend прошёл сборку и lint. После установки MSVC Build Tools и Windows SDK
успешно скомпилирована оболочка Tauri и собран NSIS-установщик версии 0.0.1
(`desktop/src-tauri/target/release/bundle/nsis/Filament Tracker_0.0.1_x64-setup.exe`,
около 22 МБ). Перезагрузка после установки Build Tools не потребовалась.
Текущая версия исходников — **0.3.11** (patch-бамп перед коммитом). Каталог данных не менялся; добавлена миграция
предзаполнения брендов. Указанный выше установщик 0.0.1 — ранее проверенная сборка;
установщик 0.3.11 пока не собран. Сборку 0.3.7 пользователь запускал самостоятельно.
В исходниках проверены миграция новой/существующей базы, отсутствие дубликатов,
сравнение версий, ошибки GitHub, авторизация API обновлений; frontend прошёл build/lint.
Установка и запуск окна пока не проверены: инструмент управления приложениями
недоступен в этой сессии. GitHub workflow ещё не запускался.
Точечные проверки backend и каталога NSIS-установщика Microsoft Defender 2026-10-31
не обнаружили угроз. Это результат для текущей сборки на этом компьютере, не гарантия отсутствия
SmartScreen или срабатываний на других устройствах.
Полный сценарий установки, обновления и удаления на чистой Windows нужно проверить
после успешной сборки оболочки. Ложные срабатывания Defender проверяются отдельно.
Добавлена ручная выгрузка резервной копии файлом из настроек десктопа.
Выгрузка и содержимое файла проверены через API; сохранение через окно WebView2
нужно проверить после пересборки установщика.
Нет облачной синхронизации, автообновления и интерфейса восстановления.
Текущие резервные копии находятся на том же диске и не защищают от его поломки.
