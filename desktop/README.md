# Десктопный прототип для Windows

Tauri открывает React-интерфейс в WebView2 и автоматически запускает упакованный
Python/FastAPI-backend. Пользователю не нужны Docker, Python, Node, Rust или свой
сервер. WebView2 устанавливается установщиком при отсутствии (для этого нужен интернет).
После установки учёт работает локально без интернета.

## Хранение и запуск

- Каталог данных: `%LOCALAPPDATA%\com.filamenttracker.desktop`.
- База: `filament.db`. Она отделена от каталога установки и не перезаписывается обновлением.
- Последние пять резервных копий перед запуском: `backups\filament-*.db`.
- Журнал ошибок запуска: `desktop.log`.
- Одновременно допускается один backend для этой базы; повторный запуск показывает ошибку.
- Backend слушает только `127.0.0.1`, порт выбирается автоматически.
- Оболочка получает одноразовую ссылку по закрытому stdout-каналу. Ссылка создаёт
  случайную httpOnly-сессию. Пароль и экран входа в локальном режиме не требуются.
- При закрытии окна или аварийном завершении оболочки закрывается stdin-канал,
  backend завершает работу. Веб/Docker-режим сохраняет прежнюю JWT-авторизацию.

Существующая серверная база автоматически не переносится. Для пробного переноса
закройте приложение и сервер, сделайте копию исходной SQLite-базы и положите её
как `filament.db` в каталог данных приложения. Не копируйте открытую базу.
Восстановление копии пока ручное: полностью закройте приложение, сохраните текущую
базу отдельно и скопируйте выбранную копию на место `filament.db`.

## Сборка на компьютере разработчика

Требуются Windows x64, Node 22+, Python 3.13, uv, Rust/Cargo (MSVC toolchain),
Visual Studio Build Tools с компонентами **Desktop development with C++**
(MSVC и Windows SDK). Это зависимости разработчика, не пользователя.

### Установка MSVC Build Tools

1. Скачайте установщик с [официальной страницы Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/).
2. Запустите его и разрешите установку в запросе Windows.
3. На вкладке «Рабочие нагрузки» выберите **«Разработка классических приложений на C++»**
   (**Desktop development with C++**).
4. Справа в составе установки проверьте наличие **MSVC для x64/x86** и
   **Windows 11 SDK** (либо Windows 10 SDK). Оставьте рекомендуемые компоненты этой нагрузки.
5. Нажмите «Установить» и дождитесь завершения. Если установщик попросит перезагрузку,
   выполните её. Затем откройте новый терминал в PyCharm.
6. Из корня проекта запустите `./scripts/build-desktop.ps1`.

Полная Visual Studio IDE не требуется. На этом компьютере WebView2, Rust toolchain,
MSVC Build Tools и Windows SDK найдены; полная сборка установщика прошла успешно.
Источник требований: [документация Tauri](https://tauri.app/start/prerequisites/).

Из корня репозитория:

```powershell
.\scripts\build-desktop.ps1
```

При нестандартном пути Python:

```powershell
.\scripts\build-desktop.ps1 -Python 'C:\path\to\python.exe'
```

Результат: `desktop/src-tauri/target/release/bundle/nsis/*-setup.exe`.
Версия установщика берётся из `backend/pyproject.toml` при упаковке.

Это служебный каталог Tauri: `target` — результаты компиляции Rust,
`release` — оптимизированная сборка, `bundle/nsis` — установщик Windows.
Готовый `setup.exe` можно скопировать в любую удобную папку и передать пользователю.
Путь к установщику не определяет расположение пользовательской базы.

## Бренды

В «Настройки → Бренды» добавьте нужные названия один раз. В форме катушки
бренд выбирается из выпадающего списка. Если справочник пуст или бренда нет,
под полем есть ссылка на настройки. Старые записи с брендом, которого ещё нет
в справочнике, сохраняют своё значение при редактировании.

## Сборка через GitHub Actions

Workflow `Desktop Windows prototype` запускается вручную (`workflow_dispatch`).
Он собирает frontend и backend, проверяет упакованный backend и создаёт NSIS-установщик.
Установщик доступен как artifact `Filament-Tracker-Windows`; релиз автоматически
не публикуется. Workflow станет доступен после отправки изменений в GitHub.

## Проверка backend

После упаковки:

```powershell
.\backend\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
```

Проверка запускает настоящий `.exe` с временной базой: миграции, доступ только
с сессией, одноразовый вход, запрет постороннего Origin, CRUD, статистика,
отказ второго экземпляра, остановка по stdin, сохранность после перезапуска
и читаемость резервной копии. Рабочую базу тест не открывает.

## Статус и ограничения

Это прототип, не готовый публичный релиз. Установщик пока без цифровой подписи:
предупреждение SmartScreen принимается как известное ограничение.
Локально успешно собран автономный backend и пройдена интеграционная проверка;
frontend прошёл сборку и lint. После установки MSVC Build Tools и Windows SDK
успешно скомпилирована оболочка Tauri и собран NSIS-установщик версии 0.0.1
(`desktop/src-tauri/target/release/bundle/nsis/Filament Tracker_0.0.1_x64-setup.exe`,
около 22 МБ). Перезагрузка после установки Build Tools не потребовалась.
По запросу пользователя версия сброшена с 0.3.6 до 0.0.1. Структура базы
и каталог данных при этом не менялись.
Перед коммитом patch-версия поднята до 0.0.2 по правилам репозитория.
Указанный выше установщик 0.0.1 относится к проверенной сборке до этого бампа.
Установка и запуск окна пока не проверены: инструмент управления приложениями
недоступен в этой сессии. GitHub workflow ещё не запускался.
Точечные проверки backend и каталога NSIS-установщика Microsoft Defender 2026-10-31
не обнаружили угроз. Это результат для текущей сборки на этом компьютере, не гарантия отсутствия
SmartScreen или срабатываний на других устройствах.
Полный сценарий установки, обновления и удаления на чистой Windows нужно проверить
после успешной сборки оболочки. Ложные срабатывания Defender проверяются отдельно.
Нет облачной синхронизации, автообновления и интерфейса экспорта/восстановления.
Текущие резервные копии находятся на том же диске и не защищают от его поломки.
